# 中心键四向快捷菜单

## 当前规则

- 当前视觉样式为裁出的遥控器方向圆环、低调功能标注、透明背景；载体 232×244 逻辑像素，放在主显示器右下角任务栏时间上方，显示后播放 480 ms 上移淡入动画。当前安装包和原生渲染证据见 `Testing/WindowsCompactRingMenu.md`；此前居中大面板截图与尺寸只描述旧版。

- 用户选择“方向键立即执行对应功能并关闭”，四个方向自由配置。
- `four_way_menu` 只允许配置在确定键长按。`actions` 的键只能为 up/down/left/right，值复用普通动作；禁止嵌套菜单，复用快捷键与鼠标/亮度参数校验。旧配置缺少菜单时语义不变。
- 方向按下时选择一次，释放和迟到的单击/双击/长按均不能再执行原映射。没有配置的方向只关闭。中心或返回取消，10 秒超时、配置修改、监听停止、断连/睡眠、暂挂和退出关闭。语音键不在普通按键枚举中，不参与菜单路由。
- 未配置普通方向动作时，菜单存在期间的捕获配合原生等价动作恢复菜单之外的方向输入；已配置的普通方向动作保留。菜单打开时清除挂起手势/连续拍，关闭后下一次按压正常识别。中心“移动光标后点击”与菜单冲突时菜单优先。
- 菜单显示就绪必须回传同一代次的 ready，显示前选择只取消、不执行动作；旧代次 ready/cancel 不得改变新菜单。静态 HTML 的名称用 JSON + textContent，窗口不激活。点击菜单（含中心区域）只取消、不执行选项；pointerdown 阻止默认聚焦，带代次的本地导航信号由宿主拦截并取消、不发网络请求。窗口失败会回传取消。

## 2026-10-12 响应速度优化

菜单窗口改为启动预加载、取消/执行后隐藏、下一次导航更新名称并复用。原先的
`destroyed=true` 只适用于旧实现；本轮验收要求同一 HWND 复用、关闭后不可见，退出时
由 Tauri 销毁。每次导航完成仍检查引擎与窗口代次，未显示前方向选择仍只取消。
冷启动预加载未完成时保留最新待展示项，完成后再导航，取消会清除待展示项。

最终原生测试确认首次请求立即进入预加载竞争路径、3 次 ready / visible /
focus_preserved / reused 均为 true、4 次 hidden 为 true（包含加载前取消），UI Automation
实际观察到三个代次对应的新名称。窗口路径耗时首次 192 ms，复用 40 / 52 ms；这些是
本机探针的请求到显示耗时，不是实体遥控器按下到功能生效耗时。完整结果见
`Testing/WindowsInputLatency.md`。

## 2026-10-12 取消问题修复

鼠标穿透已关闭，点击菜单及中心区域可以取消；打开菜单的中心长按释放沿被消费，不再补发普通单击。返回与中心按下取消的原映射/双击/长按抑制已加回归测试。最终 Windows 原生鼠标取消验证 passed，三次显示不抢焦点、点击后隐藏且前台不变、加载前取消不复活；修复包已覆盖安装并验证载荷和配置保留。

旧失败时段中心/返回新按下事件在菜单超时之后才进入语义引擎，上游迟到原因仍未知；不得据此宣称两型号按键取消真机已通过。完整记录、安装包和证据见 `Bugs/2026-10-12-four-way-menu-cancel.md`。
